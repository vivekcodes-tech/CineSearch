## 3. Backend Architecture

The backend follows a modular structure:

- `backend/app.py` – Flask application and route registration.
- `backend/routes/` – API route definitions.
- `backend/services/search_service.py` – Search and autocomplete functionality.
- `backend/services/ranking_service.py` – Ranking and recommendation algorithms.
- `backend/integrations/` – Integration adapters.
- `database/` – Database schema, data import, indexing and validation scripts.
- `tests/` – API and frontend tests.

## 4. Search and Autocomplete Integration

The backend integrates Student 1's search implementation.

Main components:

- Text preprocessing and tokenization.
- Inverted index for searching movie titles.
- Trie-based prefix autocomplete.
- Boolean AND/OR search.
- Top-K ranking for selecting relevant results.

The search service loads movie information from SQLite and returns structured movie results through Flask APIs.

## 5. Recommendation Algorithms

Five recommendation methods were integrated into the ranking service.

### 5.1 Popular Recommendations

Uses rating count and average rating to calculate a composite popularity score.

### 5.2 Genre-Based Recommendations

Filters movies according to the selected genre and ranks matching movies using their composite scores.

### 5.3 Genre-Affinity Recommendations

Builds a user genre profile from positively rated movies (rating >= 3.5), excludes previously rated movies and ranks recommendations using genre affinity and composite scores.

### 5.4 User Co-occurrence Recommendations

Identifies other users who positively rated movies also rated by the target user. It recommends unseen movies based on positive ratings from those similar users.

### 5.5 Jaccard Similarity Recommendations

Uses Jaccard similarity between the sets of users who positively rated two movies.

The implementation uses candidate intersection counts to avoid repeatedly calculating set intersections.

The optimized implementation returned five recommendations for user 94272 in approximately 4.75 seconds during one test.

## 7. Database Integration

The backend connects to the SQLite database:

`database/cinesearch.db`

The database contains movie information, genres, user ratings, tags and precomputed movie statistics.

The ranking service uses the `movie`, `genre`, `movie_genre`, `rating` and `movie_stats` tables.

The MovieLens dataset contains approximately 32 million ratings. The project imported a deterministic sample of approximately one million ratings rather than the complete ratings dataset.

The movie statistics table stores:

- Movie ID
- Rating count
- Average rating

## 10. Performance and Optimization

The initial Jaccard implementation was slow because it repeatedly calculated set intersections inside nested loops.

It was optimized using candidate intersection counts and direct union calculations.

The optimized function returned five recommendations in approximately 4.75 seconds for the tested user. This is an observed test result, not a guaranteed response time.
